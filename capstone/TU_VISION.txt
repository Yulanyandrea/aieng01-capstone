🛑 LA LÍNEA ROJA (Decisiones que NO toma Claude)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. AMBIGÜEDAD EN TAREA
   ├─ Ejemplo: DJ pide 90 min sin especificar 1 o 2 sets
   ├─ Agente hace: DETIENE y pide confirmación
   └─ DJ decide: "¿1 set de 90 min o 2 sets de 45+45?"

2. CATÁLOGO INSUFICIENTE
   ├─ Ejemplo: "90 min sin repetir artistas" pero hay pocos tracks
   ├─ Agente hace: GENERA BEST-EFFORT
   └─ Agente advierte: "⚠️ Tuve que repetir 2 artistas. ¿OK?"

3. APROBACIÓN FINAL
   ├─ Ejemplo: Agente genera playlist preview
   ├─ Agente hace: ESPERA validación DJ
   └─ DJ valida: Duración OK? Tonalidades OK? Artistas OK?
      └─ Solo después de ✅ → se genera JSON final

4. URGENCIA IMPOSIBLE
   ├─ Ejemplo: "Necesito esto en 30 segundos"
   ├─ Agente hace: ADVIERTE (mínimo viable = 2 min)
   └─ Agente NO ejecuta bajo presión

📊 TU GOLDEN SET (Caso Crítico)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

request_03_complex.txt (Alex, 90 min, 2 fases)

FUNCIONA si:
  ✅ FASE 1: exactamente 45±1 min, BPM 110-120, tonos MENORES
  ✅ FASE 2: exactamente 45±1 min, BPM 120-130, tonos MAYORES
  ✅ Sin artistas repetidos DENTRO de cada fase
  ✅ JSON: { "phase_1": [...], "phase_2": [...] }
  ✅ Explicación: por qué cada pista

FRACASA si:
  ❌ Duración fuera de rango (< 44 o > 46 min cualquier fase)
  ❌ Track fase 1 con tonalidad mayor (debe ser menor)
  ❌ Track fase 2 con tonalidad menor (debe ser mayor)
  ❌ Artista repetido en la misma fase
  ❌ JSON vacío o incompleto

🔄 FLUJO
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

2. Agente parsea: "¿90 min = 1 set o 2 sets?" → DETIENE
3. DJ responde: "2 sets de 45"
4. Agente valida: BPM + tonalidades vs catálogo
5. Agente si insuficiente: BEST-EFFORT + avisa
6. Agente propone: Preview de playlist
7. DJ VALIDA y APRUEBA ✅
8. Agente genera: 1 JSON final (ambas fases)
